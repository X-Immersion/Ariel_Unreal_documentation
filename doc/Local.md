## Nodes

Here is a quick description of all nodes related to the local executable. You can find more information on the [API Reference](/doc/API.md):

* **[START LOCAL ARIEL](/doc/API.md#start-local-ariel):** Start the Ariel local executable.
* **[STOP LOCAL ARIEL](/doc/API.md#stop-local-ariel):** Stop the Ariel local executable and clear the remaining waiting entries *(see [Local executable Lifecycle](#local-executable-lifecycle) for more details)*.
* **[Ariel Text-To-Speech Local](/doc/API.md#ariel-text-to-speech-local):** Create a local entry that will be processed by the local executable when available (if started). You can use the Event (Delegate) *[On Ariel Response](/doc/API.md#on-ariel-response)* to retrieve the generated bytes when available.
* **[Get Ariel Executable Status](/doc/API.md#get-ariel-local-executable-status-pure):** Get the Ariel local executable status.

## Local executable Lifecycle

Unlike Ariel remote requests, local requests must be processed one by one. To do that, an internal queue system have been implemented with Ariel local requests. This queue system will handle how the model is prompted in the background, meaning that you can use the node [Ariel Text-To-Speech Local](/doc/API.md#ariel-text-to-speech-local) without paying attention to the number of entries already performed.

>[!IMPORTANT]
> By default, the local executable is not running. Use the node *[START LOCAL ARIEL](/doc/API.md#start-local-ariel)* to start the Ariel local executable. You only need to call it once. It does persist even when switching levels.

>[!NOTE]
> Each time the node *[Ariel Text-To-Speech Local](/doc/API.md#ariel-text-to-speech-local)* is invoked, all given parameters are saved and an entry is added to a local queue.

Please note that the following lifecycle is executed on a separate Thread to reduce game performance impact:

0. If the local executable is not running, does nothing and wait.
1. Dequeue the first local entry. If there is no entry in the queue, does nothing and wait.
2. Check if the model name is the same as the previous request or if this is the first local request. In this case, directly skip to point (5).
3. Restart the local executable. *\**
4. Wait unitl the local executable have restarted.
5. Prompt the model with the entry parameters.
6. Return the result using the event [On Ariel Response](/doc/API.md#on-ariel-response) (Delegate)
7. Loop

*\* Restarting the executable is needed because the voice performances are drastically deteriorated if the model changes when the executable is running*

>[!TIP]
> When the local executable is stopped using the node *[STOP LOCAL ARIEL](/doc/API.md#stop-local-ariel)*, all remaining entries in the local queue are removed.

## Unreal Crash

>[!CAUTION]
>This behavior is valid for **both** editor mode and packaged projects!

If you encounter an Unreal crash while the local executable was running, please note that the local executable process **WILL NOT BE CLOSED automatically!**. This is because the local executable is not executed on the same process as Unreal, and a crash does not let Unreal 'inform' the local executable that he needs to close. We are working on a fix to close the executable even when the game crash, but for now you must do the following:

0. Close all instances of Unreal Engine
1. Open the Task Manager. See [here](https://techcommunity.microsoft.com/discussions/windows11/how-to-run-task-manager-on-windows-11-6-ways/2701239) on how to open it.
2. On the search bar, type "*piper_server.exe*"
3. End all matching occurences by clicking *End task*. If there is no result, it means that the local executable is not running and you can safely go back to work.

![Kill local executable](/res/kill_executable.png)

*Please note: The same behaviour will happen if you close the editor or the packaged game by using 'End task' with the Task Manager.*
